# Proposed disposable funded Journey policy

Owner approval required by Step 31 before implementation.

Local test chain and mock currency only. No player deposit and no player stake. A dedicated development reward pool backs a maximum fifteen whole test credits per run before funded entry is admitted: ten for the first completed checkpoint and at most five for a single eligible veteran drop. No more than fifteen credits can be promised by that reservation. Further reward sources are disabled in this first funded segment.

Bank is terminal: it ends the run and settles the earned checkpoint and extracted drop once. A new journey requires a new reservation. Quit, leader death or a twenty minute deadline forfeits unbanked newly earned rewards and releases unused backing to the pool. Previously owned assets and opened supply stock persist. There is no player deposit to confiscate.

A durable worker submits settlement and reconciles replacement and confirmation states. Independent timeout release must remain available if the game service disappears. Lack of backing disables funded entry and presents an explicit practice choice. It never changes a funded promise into simulated credits.

Use a separate companion deployment if existing vault semantics cannot express these rules. Preserve all original contracts and recovery routes. Amounts apply solely to disposable local testing and approve no public token economics or deployment.
